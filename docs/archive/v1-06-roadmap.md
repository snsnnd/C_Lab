# 06 · 实施计划、验收与风险

> 历史计划，已由 [轻量实施计划](../06-roadmap.md) 替代。本文 11–18 人周估算对应原先的重型自研路线，不适用于当前方案。

## 1. 推进原则

用户希望尽可能同时实现完整课程和自由代码可视化。因此采取：**先验证最难的真实执行链路，再并行推进课程与引擎能力，最后发布完整教学版**。

每阶段都是可检验成果；不把“页面看起来像 IDE”当作核心技术完成。

## 2. 阶段计划

以下是单名有经验开发者的粗估，不是交付承诺；课程编写、教学试用和多平台兼容会显著影响总周期。

| 阶段 | 粗估 | 主要成果 | 放行条件 |
|---|---|---|---|
| P0 技术验证 | 1–2 周 | 容器编译、GDB/MI 控制、类型/变量/数组/帧采集、事件 JSON | 代表性自由代码可观察；超时和取消可靠回收 |
| P1 教学闭环 | 2–3 周 | 左右分屏、运行和回放、输入输出、版本绑定、基础视图 | 修改代码可生成新轨迹，回退与重新播放一致 |
| P2 完整主题初覆盖 | 3–5 周 | 18 单元内容、指针/结构体/枚举/回调/多文件可视化 | 每单元有正常例、误区例、讲解与迁移任务 |
| P3 深度与准确性 | 3–5 周 | 堆生命周期、更多语义事件、诊断构建、模型标识 | 各项能力有测试和公开边界，未知不伪装确定 |
| P4 分发与教学试用 | 2–3 周 | 启动器、预构建资源、离线包、课堂试用 | 干净机器安装与课程全流程通过 |
| P5 后续拓展 | 独立排期 | 练习、课程编辑器、RISC-V 运行、浏览器轻量版 | 基于试用反馈确定优先级 |

P0–P4 粗略为 11–18 人周；如果追求广泛 C 语法的逐表达式准确动画，工作量可能远高于这个范围，需要单独研究和估算。

## 3. P0：必须先证明的技术点

先建立一个无复杂 UI 的最小采集程序，验证以下程序族：

1. 变量赋值、整数/浮点、条件与短路。
2. 循环、嵌套循环、同一行多语句、无限循环。
3. 一维/二维数组、字符串和数组参数。
4. 函数、递归、同名局部量和作用域退出。
5. 指针别名、多级指针、尾后指针和未知地址。
6. 结构体字段、填充、结构体数组及枚举名称。
7. 函数指针、注册后调用、不同策略间切换。
8. 多文件项目、静态符号、链接错误。
9. 标准输入、stdout/stderr、大量输出、取消与进程退出。
10. 分配/释放跟踪可行性，以及普通构建与诊断构建隔离。

交付：结构化轨迹样本、能力矩阵、平台元数据、限额测试结果，以及明确的保留/调整决策。

### P0 决策门

- GDB 快照足够支撑通用视图：继续主线。
- GDB 无法提供稳定的细粒度事件：保留 L2，选择少量语法做插桩实验，不承诺完整 L3。
- 采集延迟过高：先优化采样、读取和缓存，并使用“运行后回放”，不把实时目标偷换为假动画。
- 调试隔离配置不可用：修复运行器权限模型，不默认放开全部宿主权限。

## 4. 完整教学版验收

### 课程

- 18 单元均有目标、前置知识、正常例、误区例、输入及迁移问题。
- 用户要求的指针、回调、底层原理、模块化、解耦和系统架构全部有明确课程落点。
- 底层原理至少可查看平台信息、字节/布局及汇编；RISC-V 指令执行是否首版纳入须单独确认。
- 所有教学动画注明运行观测或教学模型来源。

### 自由代码

- 修改变量、循环边界、数组长度、结构体字段和回调函数后，通用图示反映新程序状态。
- 从空项目编写受支持代码也可以采集，不依赖课程 ID 白名单。
- 对自定义函数名、局部变量名、多个源文件和不同输入有效。
- 不支持的构造有能力说明和降级；不会继续显示不匹配的旧图示。

### 执行与回放

- 每条轨迹都能关联确切的源文件、输入、工具链和配置。
- 连续前进、后退、随机跳转到同一 seq 得到等价状态。
- 帧退出、对象释放与地址复用后身份仍正确。
- 旧任务事件不能覆盖新源码对应的运行结果。
- 编译失败、崩溃、超时、输出限额、事件限额、取消均有明确状态。

### 本地使用

- 在目标平台的干净测试环境中，根据发布说明启动，无需手工编译前端。
- 安装完成后断网，所有内置课程和本地运行正常工作。
- 正常退出、异常退出和取消后不遗留运行中的学生进程。
- 导出/重新导入项目后保留源码和预设输入。

### 体验与性能

- 在 1366×768 和 1920×1080 测试两栏与投屏布局；窄屏模式无不可操作的挤压。
- 小型热启动案例首批轨迹可用 p95 目标小于 2 秒，记录实际硬件、镜像与样本规模。
- 5,000 停点轨迹能按索引跳转；具体内存和响应指标由 P0/P1 测量建立。
- 键盘操作、减少动态效果、状态文字和色彩可区分性通过检查。

## 5. 测试策略

### 语义回归

使用小型 C fixtures 检查关键值、帧关系、对象生命周期和输出，而非只比较动画截图。

- 对定义良好的程序，将采集运行的输出与同配置普通运行对照。
- 引入插桩时增加差分测试，比较输出、退出状态和可观察状态，验证没有重复求值。
- 地址、线程/进程 ID 等非确定数据归一化后比较，不固定要求原始地址一致。
- UB 示例验证诊断与提示，不断言某个未定义结果必须出现。
- 单独测试递归同名变量、指针别名、地址复用、短路及 `realloc` 失败等易错场景。

### 协议与回放

- 事件 Schema、版本兼容、重复事件、事件缺口和 SSE 断线续接。
- 快照 + 差量重建，与从起点回放到相同位置结果一致。
- 数值精度、非 UTF-8 输出、不可用变量、超长数组和循环图处理。

### 运行器可靠性

无限循环、无限输出、过度分配、编译超时、重复取消、非法路径、服务重启后的残留任务清理。

### 端到端教学流程

打开课程 → 预测 → 运行 → 单步 → 改代码 → 重新运行 → 保存 → 重启恢复 → 导出导入。使用浏览器测试覆盖核心流程，再由教师实际投屏试讲。

## 6. 主要风险与应对

| 风险 | 应对 |
|---|---|
| “自由代码”范围无上限扩张 | 公开语言/库/运行能力矩阵，按功能逐项验收 |
| GDB 停点被误解成表达式级真相 | 协议标注粒度，界面区分停点、状态差分和语义事件 |
| 动画与程序不同步 | 不可变源码快照、runId、哈希校验和旧结果标识 |
| AST 插桩改变程序行为 | 限制语法、差分测试、不支持时退回快照 |
| 指针、堆对象被过度推断 | 对象代次、边界来源、未知状态和能力声明 |
| 课程量挤压引擎质量 | 统一课程包模板、通用图示组件、课程与能力对应表 |
| 学生安装成本过高 | 预构建包、环境检测、课前安装验证、参考轨迹降级 |
| 平台差异导致教材错误 | 标注 target/ABI、查询实际布局、核心例保持标准 C |
| 动画好看但学习效果弱 | 预测与解释任务、迁移练习、课堂试用反馈 |

## 7. 下一步建议

实际开发的第一个任务应是：**在隔离环境中编译一组包含循环、数组、函数、结构体和指针的自由 C 程序，通过 GDB 输出规范化轨迹，并证明可以准确回放。**

完成这个验证后，再搭建左右分屏页面。课程大纲已经覆盖全部需求，可从第一天按课程包模板编写素材，而不是等待所有高级能力开发结束。
