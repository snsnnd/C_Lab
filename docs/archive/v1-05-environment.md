## 2. 推荐补齐顺序

### 第一步：最小自由代码验证

- GDB：读取调试信息、单步、变量、调用帧。
- 包含 GCC/GDB 的受控容器镜像：验证调试权限和资源回收。
- 项目专用 Python 3.12：避免改变 Ubuntu 系统 Python。
- FastAPI、Uvicorn、pytest：进入实现阶段由 `uv` 添加和锁定。

宿主原型可参考以下命令，**本次未执行**：

```bash
sudo apt update
sudo apt install --yes gdb build-essential
uv python install 3.12
```

更推荐正式运行器把工具装进固定镜像。若全部采集工作在容器内进行，宿主无需再单独安装 GDB；学生运行时也无需安装宿主编译器。

### 第二步：语义和编辑体验

- Clang：AST、类型和布局分析。
- clangd：编辑器 LSP 诊断、补全和跳转；Monaco 本身不提供完整 C 语言服务。
- 可选 LLVM 工具：底层实验和未来 IR 插桩研究。

Ubuntu 22.04 的发行版仓库可先做原型验证；正式镜像统一 GCC、GDB、Clang/clangd 的已验证版本，避免分析器使用不同 target、头文件或宏。

### 第三步：页面与验证依赖

- 前端：React、TypeScript、Vite、Monaco。
- 图示：先 SVG，复杂关系图确有需要再加入 React Flow。
- 测试：Vitest、Playwright；Python 侧 pytest。
- 格式与检查：TypeScript 类型检查、ESLint、Ruff。

依赖写入项目清单并锁定，不要求学生全局安装这些 npm/Python 包。

## 3. 你提供的 RISC-V 工具链如何使用

Windows 访问路径：

`\\wsl.localhost\Ubuntu-22.04\home\aaa\gcc_riscv32`

WSL 内对应：

`/home/aaa/gcc_riscv32`

主要编译器：

`/home/aaa/gcc_riscv32/bin/riscv32-unknown-elf-gcc`

建议用途：

1. 生成简单函数的汇编，对照加法、循环和函数调用。
2. 观察目标 ABI、寄存器与调用约定。
3. 后续接模拟器，实现源码/汇编/寄存器联动。

需要特别明确：

- 该工具生成的 RISC-V 程序不能直接在当前 x86_64 Linux 上执行。
- `unknown-elf` 裸机程序通常还需要启动代码、链接脚本、运行库及 I/O/退出机制。
- QEMU/Spike 不是安装后就能无条件运行所有这类 ELF；需要先确定具体机器模型、ABI、ISA 扩展和加载方式。
- 第一阶段可以只做反汇编观察；指令级运行在独立技术验证后加入。
- 不要求所有新生安装该交叉工具链；使用课程内置目标镜像/素材更可控。

## 4. 开发与学生分发方案

### 开发时

- 在 WSL 的 Linux 文件系统中保存项目，减少 Windows 挂载目录带来的文件监听和权限差异。
- Vite 负责前端开发；Python 服务负责编排；Docker 只承担受控编译与运行。
- 前端开发代理转发到 API；生产模式由同源本地服务提供静态资源。
- 固定依赖锁文件、执行镜像和协议版本。

### 学生使用：推荐交付目标

一个发布包包含：预构建前端、本地服务/启动器、课程包、环境检测器、版本清单和离线参考轨迹。

启动器完成：检测平台与 Docker → 检查镜像 → 启动本地服务 → 打开浏览器 → 正常退出时清理运行任务。

学生不应手工启动 Vite，也不应每次上课运行依赖安装命令。

### 首批平台建议

| 平台 | 建议路径 | 待验证问题 |
|---|---|---|
| Windows | WSL2 + 可用 Docker 环境，浏览器访问 localhost | 学校设备虚拟化权限、Docker/WSL 安装和端口转发 |
| Linux x86_64 | 本地启动器 + Docker | 用户权限、内核限制与调试规则 |
| macOS Intel | Docker Desktop + 对应启动器 | 本地服务打包、容器权限行为 |
| macOS Apple Silicon | 原生 arm64 镜像或独立验证的兼容方案 | ABI 差异、工具链镜像、避免默认依赖慢速跨架构模拟 |

平台表是路线，不代表已经支持。先调查学生机器，再确定首个发布包的平台矩阵。

### 离线使用

- 安装包、镜像和课程可提前在校园网络分发；运行时不依赖 CDN、远程字体或在线编辑器服务。
- 首次镜像下载可能较大，课前预装；离线分发可提供镜像归档与校验值。
- 没有 Docker 的设备可以打开静态课程和参考轨迹，但不能声称支持自由代码重新执行。
- 完全免 Docker 的浏览器 WASM 版本是后续单独路线，需重新验证调试能力与语义边界。

## 5. 暂时不需要的基础设施

云服务器、账号系统、Redis、PostgreSQL、Kubernetes、GPU、大模型 API 均不是完成当前目标的前置条件。

建议开发机至少 8 GiB 内存，16 GiB 更适合同时开发和运行测试；磁盘与学生最低配置需要通过实际镜像体积及基准测试确定。

## 6. 开工前的剩余确认项

1. 学生主要使用 Windows、macOS 还是 Linux；是否有安装权限。
2. 计划总课时、每次课时长及学生是否有其他语言基础。
3. 是否必须离线首次安装，还是仅要求安装后离线使用。
4. 是否要求在第一版实际单步运行 RISC-V，还是接受后置扩展。

这些不会阻止当前 x86_64 本地采集原型的开发，但会影响发布包装与课程节奏。
