# 01 · 总体设计与交互

> 历史方案 v1，已由 [当前轻量方案](../01-product-and-interaction.md) 替代。本文中的原生调试、自研引擎和完整底层支持不是当前首版要求。

## 1. 定位与成功标准

这是一个“能修改代码的可视化实验室”，面向初学者解释 **代码执行了什么、为什么得到这个结果、数据存在哪里、模块如何协作**。

已确认使用路径：教师投屏讲授 → 发放本地版本 → 学生修改示例、自主实验 → 后续增加练习。

建议的成功标准：

- 教师改动循环边界或指针指向后，能够生成与新源码一致的执行轨迹。
- 学生可以暂停、前进、后退，对照代码说明某一步的变量和内存变化。
- 每个课程单元都有目标、示例、图示、误区和一个迁移问题。
- 课程后半段可以打开多文件项目，看懂声明、定义、模块依赖与回调注册。
- 首次启动后不依赖互联网完成已内置课程；安装和首次下载另行说明。

## 3. 工作台布局

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 课程 / 项目  保存状态  运行  停止  自动运行开关  环境: Linux x86_64       │
├──────────────────────────────┬─────────────────────────────────────────┤
│ 文件栏: main.c student.c .h  │ 视图: 执行 | 内存 | 调用 | 模块          │
│                              │                                         │
│ Monaco C 编辑器              │ 当前概念的主图                          │
│ 源码行号与执行位置            │ 例：数组格、当前索引、累加变量          │
│ 当前停留行 / 最近执行行区分   │                                         │
│                              ├─────────────────────────────────────────┤
│                              │ 本步解释 / 变化前 → 变化后              │
├──────────────────────────────┴─────────────────────────────────────────┤
│ 上一步  播放/暂停  下一步  速度  时间轴  第 12 / 38 个快照              │
├────────────────────────────────────────────────────────────────────────┤
│ 输出 | 输入 | 编译诊断 | 课程讲义    （可收起）                         │
└────────────────────────────────────────────────────────────────────────┘
```

- 默认两栏接近等宽，可拖动比例；课程目录收起，避免三栏挤压代码。
- 图中选择变量可定位其声明和对应对象；定位失败时只展示已知信息。
- 代码点击某行可查相关轨迹点，但不承诺每行有且仅有一个执行事件。
- 同一行多条语句、循环头和宏展开需要“该行有多个执行位置”的提示。
- 默认右侧只呈现当前课的主视图，内存细节按需展开，降低认知负担。

## 4. “实时”的具体含义

实时不是每敲一个字符就启动程序，而是分成三个反馈层：

1. **编辑反馈**：语法、符号和类型诊断；优先响应输入。
2. **执行反馈**：手动运行，或在启用自动运行后停止输入约 800 ms 发起任务。
3. **播放反馈**：新轨迹可用后，按教学节奏重放；动画速度与程序真实运行速度无关。

自动运行规则：

- 同一工作台最多一个运行任务；新版本取消旧任务或等待旧任务退出，禁止无上限排队。
- 使用源码哈希和 `runId` 判断结果归属，旧结果不能覆盖新代码。
- 修改代码立即标记当前动画“来自上一次运行”，保留旧轨迹供对照。
- 运行失败时保留上次成功结果，但显著显示版本不一致；不能让学生误以为新代码成功。
- 默认预先填写 stdin 后运行。运行中的交互式输入留到后续，以降低调试控制复杂度。
- 自动运行默认关闭；教师可以对短小示例开启。

## 5. 一次教学交互示例：数组累加

1. 打开课程中的五元素数组求和示例。
2. 先让学生预测结果，再运行，避免只观看动画。
3. 主图显示五个数组单元、当前索引和 `sum`。
4. 到达赋值后的快照时，展示 `sum` 的前后值；课程语义层可分解读取、计算、写回。
5. 点击数组，展开元素类型、元素大小、连续布局和实际/逻辑地址。
6. 把循环边界改错，重新运行，通过边界分析或诊断报告讨论越界。
7. 回到正确版本，将求和抽成函数；观察参数、局部变量和返回值。

仅由行级快照观察到的值变化，使用“这两个停点之间发生变化”的措辞；不能断言中间每次读写的顺序。

## 6. 两种使用模式

### 教师模式

- 投屏字号建议 20–24 px，可进一步放大；一键隐藏无关面板。
- 课程章节和演示步骤快捷切换；关键步骤可以配置提问停点。
- 提供“只看源码”“只看图示”“代码与图示并排”三种焦点布局。
- 提前生成的参考轨迹用于无执行环境时讲解，并标明“预录轨迹”；改动代码后必须重新执行。

### 学生模式

- 每课按“预测 → 运行 → 解释 → 修改 → 迁移”推进。
- 本地自动保存、恢复课程原例、另存副本、导出代码与输入。
- 显示术语解释，讲义可折叠；先使用变量盒子，再逐步展示字节与地址。
- 练习阶段可在已有课程包基础上增加任务和检查器，不重做执行引擎。

## 7. 图示语言与可访问性建议

本节是交互约束草案，不是已确认的视觉品牌规范。

- 以课堂可读性为先：浅色高对比默认主题，暗色可选；真实投影环境下确认效果。
- 中文使用清晰无衬线字体，代码使用等宽字体；字体本地提供或使用系统回退。
- 变量、地址、类型、当前步骤保持固定视觉编码，避免不同课程重新定义颜色意义。
- 颜色必须配合文字、边框或图标；错误与正常状态不能只靠红绿区分。
- 改值动画建议 150–300 ms；提供减少动态效果模式，保留清晰的前后状态。
- 支持键盘控制和可见焦点；编辑器内的空格、方向键不被播放器快捷键截获。
- 正文对比度目标至少 4.5:1；图示同步提供文本表格，屏幕阅读器能理解关键变化。
- 主要适配桌面/笔记本与投屏；窄屏切换“代码/图示”标签，不压缩成两列小字。
- 大数组默认显示窗口及总长度，完整内容按需查看；复杂指针图允许聚焦局部对象。

## 8. 必须设计的状态

未运行、源码已修改、准备环境、编译中、执行中、轨迹采集中、可播放、编译失败、异常退出、超时、事件截断、用户取消、输入耗尽、引擎能力不支持、后端不可达。

每种状态必须说明：当前发生了什么、已有图示对应哪个源码版本、用户下一步可以做什么。
