# 03 · 技术架构与可视化引擎

> 历史技术路线，已由 [复用优先架构](../03-architecture.md) 替代。GCC/GDB 自研采集链路已移出当前实施主线。

## 1. 核心决策

采用 **本地 Web 应用 + 原生 C 执行 + 轨迹采集/回放 + 渐进式语义增强**。

| 层 | 推荐选择 | 原因 |
|---|---|---|
| 页面 | React + TypeScript + Vite | 编辑器与复杂状态适合组件化，本地应用不需要 SSR |
| 代码编辑 | Monaco Editor | 多文件、诊断标记、源码定位、成熟的编辑体验 |
| 可视化 | SVG + React；复杂关系图按需用 React Flow | 数组、结构体布局和连线易于交互与文本替代 |
| 状态 | 工作台状态 + 独立纯函数轨迹 reducer | 播放状态与执行状态分离，便于回放与测试 |
| 本地服务 | Python 3.12 + FastAPI，由 uv 管理 | 编排进程、结构化协议与内容处理方便 |
| 运行器 | 固定版本 GCC + GDB/MI | 执行真实 C 程序，能读取 DWARF 调试信息与停点状态 |
| 静态语义 | 固定版本 Clang AST / clangd | 类型、源区间、符号和诊断；不是运行状态来源 |
| 隔离 | Docker 执行镜像，每次运行单独沙箱 | 控制资源、文件和系统调用，方便学生使用一致环境 |
| 保存 | 版本化 JSON、课程资源与本地工作区 | 首版不需要数据库服务；SQLite 可后续用于历史索引 |
| 测试 | pytest、Vitest、Playwright | 分别验证采集/协议、回放逻辑、完整教学流程 |

上述为拟定选型。具体依赖版本在技术验证完成后锁定，镜像用 digest 标识。

### 备选路线取舍

| 路线 | 长处 | 主要问题 | 本项目决策 |
|---|---|---|---|
| 每课写固定动画 | 上手快、讲解可控 | 代码改动后容易失真，不能实现自由代码 | 仅用于明确标注的概念模型 |
| 自己实现 C 解释器 | 易获取表达式级事件 | C 语义、库和 UB 很难正确覆盖 | 不作为主线 |
| GDB 调试采集 | 真实执行、初期成本可控 | 行级采样、不完整的表达式/读写信息 | 首选通用底座 |
| Clang AST 插桩 | 可以产生更细事件 | 求值次数、顺序、宏和源码映射复杂 | 验证后限制范围引入 |
| LLVM IR 插桩 | 能观测底层 load/store | 源码语义映射和调试工具开发成本高 | 研究扩展，不是首版前提 |
| 浏览器 WASM | 容易分发、浏览器隔离 | C 工具链体积、调试能力和内存模型需重做 | 保留后续简化分发路线 |
| 全程 RISC-V 模拟器 | 指令和寄存器可控 | libc、系统调用、机器模拟和源码映射增加范围 | 底层课程独立实验 |

## 2. 模块关系

```text
浏览器工作台
  ├─ 编辑器 / 课程面板
  ├─ RunClient（运行请求、取消、事件接收）
  └─ TraceStore → PlaybackReducer → ViewModels → SVG/图表
             │ HTTP + SSE
本地 API 服务
  ├─ ProjectService：文件版本、源码快照、导入导出
  ├─ LessonService：课程包、提示、视图选择
  ├─ RunService：任务状态、限额、事件存储
  └─ RunnerAdapter：创建沙箱、编译、调试采集、销毁
             │ 容器进程/结构化消息
每次运行的隔离环境
  ├─ CompilerAdapter：GCC / 可选诊断构建
  ├─ DebuggerAdapter：GDB/MI 控制、停点与变量采集
  ├─ Symbol/TypeExtractor：DWARF、可选 AST
  └─ EventNormalizer：统一事件、来源与置信说明
```

前端不解析 GDB 输出；后端不根据某课标题生成伪造变量值。课程系统通过视图配置和已知符号选择关注对象，不侵入编译运行主链路。

目录建议：

```text
apps/web/                 前端工作台
services/api/             本地接口和任务编排
services/runner/          编译、调试适配、隔离和事件标准化
packages/contracts/      JSON Schema、生成的类型、协议样例
packages/visualizers/    与课程无关的通用图示组件
lessons/                 课程包、源码、说明和参考输入
runtime/                 执行镜像与工具链配置
tests/fixtures/          可重复 C 程序及预期语义
docs/                    本次设计文档
```

## 3. 一次运行的生命周期

1. 冻结源文件、stdin、编译配置和课程版本，计算哈希。
2. 检查文件名、大小、允许的后缀和项目相对路径；使用受控编译参数。
3. 创建独立沙箱，复制本次运行文件；编译也在沙箱内。
4. 以 C17 教学配置编译：`-std=c17 -g3 -O0 -fno-omit-frame-pointer -Wall -Wextra -Wpedantic`。
5. 生成诊断；编译失败结束任务，不生成新执行轨迹。
6. 通过 GDB/MI 启动程序，跳过启动库代码，在用户源码范围采集停点。
7. 读取当前帧、可见变量、类型、受限对象内存以及输出；将差分写入轨迹。
8. 达到退出、错误、用户取消或资源限制时生成终态，清理整个进程组/容器。
9. 前端接收事件分块；达到可播放条件后回放已采集部分，不能访问尚未生成的步骤。

`-O0` 只提升可观察性，不保证“每个源码语句对应一个停点”，也不能消除 UB。

## 4. GDB 采集的实现约束

- 使用 MI 结构化协议及命令 token；异步通知、命令结果和 inferior 输出分别处理。
- 明确变量快照对应“停在下一处源码位置、尚未执行该位置”的时刻。
- 源位置作为一个集合/区间处理，不能假设行号连续递增。
- 用 source-step 进入用户函数，在库函数处 step-over/finish；具体策略由技术验证选择。
- 若一步跨过多个调用帧，不能虚构中间完整调用序列。需要更精确时加用户函数入口/返回的跟踪。
- 调试器与程序的 stdin 分离，MI 控制流不能混入学生输入；stdout/stderr 独立捕获。
- 只允许内部构造的只读变量/内存查询，不执行学生输入的 GDB 命令，不通过求值调用用户函数。
- 关闭调试器自动加载脚本、初始化文件等非必要扩展。
- 对字符串长度、数组元素、递归深度、指针追踪深度和读取字节数设定上限。
- GDB 已读出的局部变量字节不等于“语言层面已经初始化”；结合语义信息，否则显示未知有效性。

### 动态内存

仅靠普通局部变量快照不足以确定堆对象边界。需单独验证分配跟踪适配器：

- 在允许的分配/释放入口和返回处记录调用参数、返回地址与分配代次。
- 首先支持标准 `malloc/calloc/realloc/free`，自定义分配器不自动推断。
- `realloc` 失败、地址不变、地址改变和释放需要分别处理。
- 跟踪器实现可以选择受控包装库或调试断点；对语义/地址的影响必须记录。
- 若该能力不可用，显示原始指针值和“对象边界未知”，不绘制虚假的完整堆对象。

## 5. 可视化能力分级

每次运行返回能力清单；界面按实际引擎能力展示。

| 等级 | 可保证的内容 | 典型限制 |
|---|---|---|
| L1：编译与运行 | 诊断、标准输出、退出信息 | 没有可用调试信息时降级到本层 |
| L2：停点快照 | 用户源码位置、可见局部量、数组、结构体、调用帧 | 不能恢复停点之间全部读写 |
| L3：语义增强 | 经验证的分支结果、循环阶段、堆生命周期或表达式事件 | 按 feature 标识开放，不声称覆盖所有语法 |
| L4：机器观察 | 目标架构反汇编、寄存器、指令单步 | 指定平台，独立运行配置 |

首版自由代码目标为稳定 L2；课程例按需具备 L3。自由代码在引擎支持的语法与运行约束内，不能仅因它不是预设示例而拒绝显示通用状态。

### 为什么 AST 不能独自生成执行动画

AST 可以描述“这里有加法、这里有函数调用”，却不知道本次输入使条件成立与否，也不知道指针实际指向哪里。运行数据决定实际状态，AST 提供解释和定位。

表达式插桩必须验证：短路、逗号运算符、自增、函数参数求值、`volatile`、宏和多次求值等。未经验证的构造退回 L2，而不是自动重写。

## 6. 自由代码的公开支持边界

### 完整教学版目标

- C17 的教学常用子集，单线程、确定的预设输入、有限运行时间。
- 标量、枚举、固定大小数组、结构体、普通函数、递归和函数指针。
- 指针视图支持已知对象/子对象内的关系；未知地址保留数值及状态。
- 标准分配函数的堆生命周期，通过专项验收后开放。
- 多个受控 `.c/.h` 文件，允许列表内的标准库能力；不能上传任意构建脚本。

### 初版明确不保证精细可视化

多线程/多进程、网络、内联汇编、信号、`setjmp/longjmp`、复杂宏、任意外部库、自定义分配器、位域/联合体的完整读写解释、变长数组的全部边界语义。

能编译执行但无法精细展示的内容采用降级；涉及不允许的系统能力则拒绝执行并解释原因。

## 7. 语义真实性

所有图示标注数据性质：

- **运行观测**：来自本次调试器快照/跟踪事件。
- **静态信息**：声明、类型和候选调用关系。
- **教学模型**：为了说明概念而分解的过程。
- **未知/不可用**：没有足够证据，不能当作 0 或空指针。

地址采用两种显示方式：默认稳定逻辑对象标签，展开可看本次真实地址。地址受 ASLR、平台和诊断构建影响，不作为跨运行比较键。

结构体偏移、`sizeof`、字节序从实际目标和调试信息获得。静态 Clang 分析必须匹配 GCC 的 target、宏、include 和 ABI；不一致时以实际构建信息为准并提示差异。

模块图分别显示 include 依赖、符号调用依赖和教师声明的逻辑分层，不能把头文件引用数量直接当作耦合度结论。函数指针候选调用与本次实际调用边分开。

## 8. 诊断构建与未定义行为

- GCC 警告和静态规则用于早期反馈。
- 按需单独运行 AddressSanitizer/UndefinedBehaviorSanitizer 诊断构建。
- 诊断运行具有独立 `runId`、工具链配置和日志；不能把其中的地址直接关联到普通运行对象。
- ASan 需要较大虚拟地址空间，单独制定容器内存/地址空间策略，不能简单复用普通运行的 `RLIMIT_AS`。
- 未初始化读、所有边界错误和所有 UB 并非上述工具都能发现。
- 一旦检测到 UB，标记检测点后的轨迹为不具有语言语义保证；课程不继续把结果解释成标准规定。
- 没检测到错误时也不生成“程序没有 UB”的结论。

## 9. 执行隔离是运行器的一部分

本地学生程序可能出现无限循环、无限输出或错误文件操作，因此隔离直接服务于可靠教学。

- 服务默认绑定 `127.0.0.1`；校验 Host/Origin 与本地会话令牌，避免网页跨站触发本地运行。
- 每任务独立非 root 容器；无网络、只读根文件系统、受限临时目录，不挂载学生主目录或 Docker socket。
- 丢弃不必要 capability、启用 `no-new-privileges`、限制进程数、内存、CPU 和输出。
- GDB 需要跟踪自己的子进程：验证最小 ptrace 权限和 seccomp 规则；不得直接使用 `--privileged`。
- 编译器也处理非可信输入，必须有编译超时和资源上限。
- 构建参数由服务生成，不执行用户 shell 命令或 Makefile。
- 导入文件限制数量/大小，拒绝路径穿越和符号链接逃逸。
- 无可用隔离环境时仍可读课和播放参考轨迹，但不静默退回宿主执行。

建议初始限额，技术验证后调整：

| 项目 | 普通教学运行建议值 |
|---|---|
| 编译墙钟超时 | 10 秒 |
| 采集墙钟超时 | 30 秒，含 GDB 交互开销 |
| 容器资源 | 1 CPU、512 MiB 内存、最多 64 个进程 |
| 轨迹停点 | 5,000 个，达到上限明确标记截断 |
| 输出 | stdout/stderr 合计 1 MiB |
| 源码 | 最多 32 文件、总计 1 MiB |
| 数组显示 | 默认 64 元素，单对象读取设额外字节上限 |

这些是资源策略起点，不是已经测得的容量；诊断构建另设资源档位。

## 10. 回放、性能与可维护性

- 上一步是回放已记录状态，不是让真实进程逆执行，也不撤销文件/输出副作用。
- 源码修改后开启新运行，不能从旧快照接着执行新源码。
- 使用定期完整快照 + 差量事件；拖动时间轴从最近快照重建状态。
- 运行、采集、播放各有自己的状态机；网络慢不应改变事件含义。
- SSE 批量推送与背压控制，前端按帧合并渲染；超额时截断而非无限内存增长。
- 普通小示例目标：热环境编译与首批轨迹可用 p95 小于 2 秒。此为待测目标，不是承诺所有程序即时完成。
- 统一协议用 JSON Schema 校验，Python/TypeScript 类型从同一协议生成或校验。
- 不从第一版拆成网络微服务：保持模块化单体与独立运行器边界，降低学生部署成本。
