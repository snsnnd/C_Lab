## 2. 实施中发现并解决的问题

- **添加注释后解析失败**：注释节点参与 AST 子节点遍历，可能被误当语句或声明符。现在解析前将字符串、字符字面量之外的 `//` 和 `/* … */` 替换为空白，保留行号；多文件预处理也忽略被注释的 include，并允许头文件保护指令后的注释。未闭合块注释给出诊断。

- **没有任何现成引擎可用**：实测确认 persistent-c 不支持 enum 与函数指针、且依赖原生二进制；Codecast 需要服务器与凭据。因此改为 tree-sitter-c 解析 + 自研求值器。这是本次最大的工程投入。
- **求值器调试中修掉的真实缺陷**（均由测试固定）：结构体标签名被误当 typedef；`field_identifier` 漏判导致所有结构体字段被丢弃；`int (*cmp)(int,int)` 因声明符绑定方向错误被解析成「返回指针的函数」；数组向指针的自动转换缺失；`primitive_type` 被当作含子节点的说明符导致 `double` 变成 `int`；`else_clause` 节点未处理。
- **显示用字符串转义污染了语义**：`readCString` 为显示把控制字节转义成 `\x0a` 文本，被用来解析格式串时会出错。已拆成「原样读取」与「显示转义」两个函数。
- **机器速度输入时的 React 更新深度告警**：`pressSequentially({delay:0})` 这类自动化输入会触发 `Maximum update depth exceeded`，真人速度输入、粘贴与文件导入均不触发，内容也不丢失；已加程序化回写抑制，仍会偶发，记为已知问题（仅开发态告警）。
- **开发服务器下 WebAssembly 加载失败**：`web-tree-sitter` 用 `new URL("web-tree-sitter.wasm", import.meta.url)` 定位自身运行时，被 Vite 预打包后该 URL 指向 `/node_modules/.vite/deps/`，文件不存在，SPA 回退返回 `index.html`，于是出现 `expected magic word ... found 3c 21 64 6f`（`<!do`）。已在 `vite.config.ts` 中把 `web-tree-sitter` 排除出 `optimizeDeps`，并为两处 wasm 加载补充 magic word 校验与中文错误提示。
- **左侧高亮永远停在第 1 行**（用户反馈后定位）：AST 解析器被缓存成 `new Parser('')`，没有源码可数，`lineOfOffset` 恒返回 1，于是所有语句行号都是 1；运行时错误的行号也同样错误。改为每次执行用真实源码新建解析器，只缓存 tree-sitter 解析器（顺带修掉跨运行残留 typedef/标签的问题）。
- **switch 与 while 的判断没有步骤**：`snapshotOf` 会跳过「什么都没变」的语句，条件判断、`break` 都不产生快照，所以条件行永远高亮不到，也没有分支图。现在 `if/switch/循环` 在每次判断后发出 `branch` 事件并强制产生一个停点，附带可读结论与全部去向；`break/continue/return` 同样强制停点。
- **停点取的是执行前的状态**：变量变化被记到「下一条语句」的行上（例如 `i++` 的结果显示在 `while` 行）。改为语句执行后再取停点，让变化与造成它的行永远同框。
- **`default:` 从来没生效**：tree-sitter 用 `case_statement` 表示 `default:`，代码却只认 `kind === 'Default'`，导致 default 分支永远匹配不上。
- **`main` 的返回值被丢掉**：`run()` 里 `done` 事件写死 `exitCode: 0`，界面「执行结束 · 返回 0」永远成立。现在取 `main` 的真实返回值。
- **输出只在结束时出现**：`outputBound` 定义了却没接上，执行过程中的 `printf` 不会成为停点。已接到解释器的 `onOutput`。
- **编辑器的 React 内部告警**：`@uiw/react-codemirror` 与图示组件「空状态→数据状态」的整树替换都会触发 React 19 开发态内部不变量日志。已分别改为直接集成 CodeMirror 6、让三种可视化分支共用稳定根节点。

## 3. 架构与进阶扩展已交付

用户确认选择可运行的 C 模块课程后，已增加第 15–18 课。使用各翻译单元独立的解析上下文；链接外部函数和对象，文件级 static 保持隔离。快照与诊断映射回原文件、原行，跨模块回放自动切换编辑器文件。

随后按要求扩展常见 C 用法并增加最终章：第 19–22 课覆盖宏定义与展开、条件编译、静态局部变量与位标志、动态内存；第 23 课是可运行的学生成绩管理系统（7 个文件、命令式输入、增删改查与统计）。宏课可展开运行前的预处理结果，回放仍定位原始源码行。

最后按要求加入课堂同步：`server/serve.mjs` 同时托管构建产物与同步接口（`POST /api/publish`、`GET /api/events` SSE、`GET /api/room`）。老师广播工作区与播放步骤，学生只读跟随，退出后恢复自由编辑。实现中修掉一个真实竞态：老师的主讲事件流可能在首次发布前订阅，服务端原先会直接拒绝；现在只在密钥已注册且不匹配时拒绝。SSE 需在反向代理处关闭缓冲。

同步修复的问题：原解析器对 extern/static 声明符位置的假定、后出现的函数原型覆盖定义、typedef 函数指针形参退化成 int；静态局部变量每次调用被重置、连续 `scanf` 不推进输入位置、宏展开后的数组长度表达式只认字面量、`constantInt` 不支持枚举与运算表达式、`unsigned char` 被误当有符号、数值字面量把十六进制后缀当数字、`strcpy` 返回值错误、`malloc/calloc/fgets/strcpy` 的返回类型固定为 int。新增链接、预处理、GCC 对照测试覆盖这些场景。

当前边界是平级小型教学项目：`#line`、GNU 专用宏扩展、子目录及完整构建系统仍未实现；标准库为教学子集，整数运算受 JavaScript 安全整数范围约束。
