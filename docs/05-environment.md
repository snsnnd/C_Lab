2026-10-07 已检查：uv 0.11.17、Node 24.11.1、npm 11.6.2、Python 3.10.12、宿主 GCC 11.4.0、Docker 29.8.0 且服务端可连接，make/cmake/git 在 PATH。GDB、Clang 未在 PATH 找到。

**新方案不要求现在安装 GDB、Clang、额外数据库或云服务。** 先验证选中的开源底座，再安装它实际需要的依赖。

## 2. Codecast 验证需要留意

以下来自上游 README/package.json，不表示本机已经验证成功：

- 项目使用 Node、Yarn、Git 子模块及特定 `@france-ioi` 包。
- README 要求配置 GitHub Packages 访问令牌；如果当前仍需凭据，应由开发者在本机配置，不能放进发给学生的包。
- C 转换依赖 `c-to-json`，README 提供 Linux 二进制，并提到 `libncurses5`。
- 完整平台涉及 MySQL 和 S3 录课存储；哪些可以不启用、离线包是否可重新处理修改后的源码，必须实测。
- 当前 package.json 的版本要求可能与 Node 24.11.1 存在细节差异；根据锁定提交核对 engines 与构建日志，不先升级全部系统软件。
- `persistent-c` 的公开源码、包仓库版本和上游依赖版本是否对应，需要在验证时固定下来。

不要直接照抄上游旧教程中的云存储公共访问配置；本项目当前不需要云录课存储。

## 3. 学生分发目标

优先实现：**解压发布包 → 启动 → 浏览器打开 → 选择课程**。学生不需要 npm 开发环境，不需要 GitHub 令牌。

实际可采用的形式取决于验证：

| 验证结果 | 发布形式 |
|---|---|
| 编译/解释链能完全本地浏览器运行 | 预构建资源 + 简单本地静态服务/启动器 |
| 需要本地源码转换服务 | 前端 + 预构建 Node 服务 + 转换工具，按平台打包 |
| 转换工具仅 Linux 易用 | 教师 WSL 先试用；学生平台支持另作准入条件 |
| 离线只支持预录/预转换场景 | 明确标注仅课程回放，不称为离线自由代码环境 |

不能把 `yarn pack-offline` 存在直接等同于“离线任意 C 代码都能运行”。修改代码并断网重新执行是关键验收步骤。

## 4. GCC 的轻量用途

开发者用宿主 GCC 验证所有正常课程源码。架构课附多文件源码和受控构建说明，让有本地编译器的学生独立运行。

基础浏览器课程不依赖学生安装 GCC。若后续加入本地原生运行按钮，再补充隔离、超时和文件限制；本次不为尚未启用的功能建设完整运行器。

## 5. 仍需确认的发布条件

学生操作系统与安装权限、是否要求首次安装也完全离线、实际课时安排。优先在 Windows/WSL 教师机验证，再根据学生设备决定平台矩阵。

本轮仅做网络资料核实和文档修订，没有安装依赖或尝试构建上游项目。
