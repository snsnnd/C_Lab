控制流面板是全课程共用的图示：每一步都显示这次判断的结论与全部去向，switch 会列出所有 case 并把未命中的置灰，循环会显示进行到第几轮以及退出条件。左侧高亮行与右侧图示来自同一个快照，逐步播放时同步移动。

课程代码刻意保持在一屏到两屏之内，便于课堂上快速通读。

## 2. 课程编排原则

- **先预测再看答案**：每课先让学生预测结果，避免只观看动画。
- **一个概念一课**：指针课只讲指向关系与解引用，不混入内存布局。
- **边界值优先**：条件课用 59/60/61，循环课用 `<` 与 `<=` 的差异。
- **参数化示例**：数组元素、循环上界、输入数据都是可直接改写的具体数字。

## 3. 初学者仍需理解的底层常识

只保留能直接解释代码的部分：变量有类型；数组元素有顺序和边界；指针保存指向信息；局部变量有作用域；字符串依赖终止符。

不要求记忆地址、ABI 或汇编，也不展示虚构的机器地址。

## 4. 内容正确性红线

已在实现与文案中遵守：

- 未初始化值显示「未初始化」，不显示 `0`。
- 数组不是指针；界面明确区分数组格与指针盒，并在传参处按 C 的数组退化规则处理。
- 指针箭头表示逻辑指向关系，不是本机地址。
- 结构体字段偏移、`sizeof`、指针宽度都按 x86-64 模型给出，界面标注平台，不暗示「所有平台都这样」。
- 枚举显示常量名，但同时保留数值，不暗示枚举就是字符串。
- 回调显示函数指针指向哪个函数；它默认是同步调用，不暗示线程或异步。
- 高亮行是解释器停点，同一行可能有多个状态，不等于求值顺序。
- 数组游标由索引变量绘制，不代表检测到一次内存读取。
- 同一个变量名的不同作用域实例分别显示，不合并。

## 5. 软件架构与进阶模块的课堂用法

第 15–18 课位于 `src/data/architectureLessons.ts`，第 19–22 课与第 24–27 课位于 `src/data/advancedLessons.ts`，最终章位于 `src/data/studentSystemLesson.ts`。建议先完成函数、指针和回调课程，再进入架构与进阶模块。

1. 先读头文件，预测模块对外承诺什么。
2. 运行项目，用 Alt + 方向键逐步观察进入、返回和源文件切换。
3. 修改一个实现，再运行，判断哪些调用者需要变化。
4. 故意删除声明、重复定义符号或移除头文件，观察诊断。
5. 完成每课讲义中的重构任务，检查输出是否符合预期。

源码包含关系和运行时调用层分别标注，不能用包含箭头推断一定发生了调用。课程项目已与 GCC 多单元编译结果对照。

进阶课补充说明：

- 第 19 课可展开「查看预处理结果」，对照宏展开与原始高亮行；宏不产生调用帧。
- 第 20 课把配置放进 `config.h`，让学生改宏后重新运行，观察条件分支切换。
- 第 22 课关注申请检查、使用与释放的完整流程；释放后通过指针访问属于未定义行为，不会被自动检测。
- 第 23 课是 60 分钟综合项目，建议按「读接口 → 运行预置流程 → 改规则 → 加功能」四步展开；预置输入覆盖成功、重复、修改、删除与统计。
